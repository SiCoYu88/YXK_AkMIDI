# AkMIDI 使用文档

本文假定 AkMIDI 已安装到目标工程的 `Plugins` 目录、编译成功并可在 Unreal Editor 中使用。本文只介绍运行时用法，不包含安装、移植或版本适配。

## 功能与路由

AkMIDI 使用 `UAkMidiComponent` 连接 Unreal、Wwise 和外部 MIDI 设备，主要支持三种路由：

| 输入 | 输出 | 用途 |
| --- | --- | --- |
| Unreal | Wwise | 蓝图或 C++ 创建 MIDI 消息并驱动 Wwise Event |
| Unreal | 外部设备 | 将蓝图或 C++ 创建的 MIDI 消息发送到硬件或虚拟 MIDI 端口 |
| 外部设备 | Wwise | 接收 MIDI 键盘等设备的消息并转发给 Wwise Event |

当前 `Wwise2025.1.9` 实现不应使用“外部设备 -> 外部设备”直通：外部输入队列只在 Wwise 输出路径中消费。

## 主要类

### `UAkMidiComponent`

核心运行时组件，继承自 `UAkComponent`。在 Actor 上添加一个 `Ak MIDI Component` 后，通过它选择输入源、输出目标、收发消息和管理设备。

| 接口 | 说明 |
| --- | --- |
| `GetMidiDevice(InputDevices, OutputDevices)` | 初始化 MIDI 输入/输出对象，枚举设备并设置外部输入回调 |
| `OpenMidiInputDevice(InputPort)` | 选择 Unreal 虚拟输入或打开物理输入端口 |
| `OpenMidiOutputDevice(OutputPort)` | 选择 Wwise 虚拟输出或打开物理输出端口 |
| `CloseMidiDevice(ClosePort)` | 关闭输入、输出或两者，并将相应路由设为 `None` |
| `PostMidiEvent(Messages, AkEvent)` | 将一组消息发送到当前输出目标 |
| `StopMidiEvent(AkEvent)` | 停止指定 Wwise Event 上的 MIDI 播放 |
| `MidiFxBypass(IsBypass)` | 控制是否旁路组件的 MIDI FX |
| `InsertMidiFx(MidiMessage)` | 可在蓝图子类中重写的 MIDI FX 入口 |
| `GetInputSource()` | 返回当前输入源 |
| `GetOutputTarget()` | 返回当前输出目标 |
| `OnMessageReceived` | 收到外部 MIDI 消息时触发的蓝图事件 |

关键行为：

- 组件默认输入源为 `Unreal`，默认输出目标为 `Wwise`。
- 输出到 Wwise 时，`AkEvent` 参数为空会回退到组件自身的 `AkAudioEvent` 属性。
- Unreal 主动调用 `PostMidiEvent` 时，输入源必须为 `Unreal`，否则返回 `false`。
- 输出到外部设备时，`AkEvent` 可以为空，`NoteOffset` 不参与外部设备发送。
- `StopMidiEvent` 只用于 Wwise 输出；外部设备应发送对应的 Note Off。
- `MidiFxBypass(false)` 表示启用 FX，`MidiFxBypass(true)` 表示旁路 FX。

### `UAkMidiMessage`

一条可编辑的 MIDI 通道消息。

| 属性 | 类型 | 说明 |
| --- | --- | --- |
| `NoteType` | `EAkMessageType` | MIDI 消息类型 |
| `Channel` | `uint8` | 零基 MIDI 通道，使用 `0-15` |
| `NoteOffset` | `int32` | 相对当前 Wwise 音频帧的采样偏移 |
| `Data01` | `uint8` | 第一数据字节，含义由消息类型决定 |
| `Data02` | `uint8` | 第二数据字节，含义由消息类型决定 |

默认值为 Note On、通道 `0`、偏移 `0`、音高 `60`、力度 `72`。

### `UAkMidiFunctionLibrary`

蓝图函数库，对常用组件操作进行封装。

| 接口 | 主要参数 | 返回值/行为 |
| --- | --- | --- |
| `CreateAkMidiMessage` | 类型、通道、偏移、Data01、Data02 | 创建并返回 `UAkMidiMessage` |
| `ModifyAkMidiMessage` | 消息、字段类型、值 | 修改指定字段 |
| `PostMidiEvent` | 组件、消息数组、Event | 返回组件发送结果 |
| `StopMidiEvent` | 组件、Event | 组件有效时返回 `true`，不会透传底层停止结果 |
| `OpenMidiDevice` | 组件、`EIOType`、Port | 打开输入、输出或两者 |
| `CloseMidiDevice` | 组件、`EIOType` | 关闭输入、输出或两者 |

注意：

- `OpenMidiDevice` 使用 `IO_Both` 时，会把同一个 `Port` 同时用于输入和输出。物理输入、输出的端口编号彼此独立，需要选择不同端口时应直接调用组件的两个 Open 接口。
- `ModifyAkMidiMessage` 的值参数为 `uint8`。需要设置大于 `255` 的 `NoteOffset` 时，应在创建消息时传入，或直接设置消息属性。
- 如果调用方需要知道 Wwise 是否确实停止成功，应使用组件的 `StopMidiEvent` 返回值，而不是函数库包装。

### `UAkMidiFxLibrary`

内置 MIDI 处理函数，直接修改并返回传入的消息对象。

| 接口 | 说明 |
| --- | --- |
| `Octave(MidiMessage, Octave)` | 对 Note On 的音高增加 `Octave * 12` |
| `VelocityCompression(MidiMessage, Low, High)` | 将 Note On/Off 力度限制在 `[Low, High]` |

`Octave` 只处理 Note On，不处理 Note Off，且最终音高不会自动限制到 `0-127`。实际使用时必须让 Note On 和 Note Off 应用相同的音高变化，并自行做范围限制，否则可能出现音符无法关闭或 `uint8` 溢出。

### `UAkMidiDevice`

对 RtMidi 输入和输出对象的底层封装。一般不需要直接创建或调用，由 `UAkMidiComponent` 管理。

### 模块类

`IAkMidiModule` 和 `FAkMidiModule` 负责 Unreal 模块生命周期，正常使用时不需要直接操作。

## 数据结构与枚举

### `FMidiDevice`

设备枚举结果。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `Name` | `FString` | 操作系统返回的设备名，或 `Unreal`/`Wwise` 虚拟端点名 |
| `Port` | `uint8` | 传给 Open 接口的真实端口号 |

必须使用 `FMidiDevice.Port` 打开设备，不要把设备在数组中的下标当作端口号。

### `EMidiInputSource`

| 值 | 说明 |
| --- | --- |
| `Unreal` | 消息由蓝图或 C++ 创建 |
| `ExternalDevice` | 消息来自外部 MIDI 输入设备 |
| `None` | 输入已关闭 |

### `EMidiOutputTarget`

| 值 | 说明 |
| --- | --- |
| `Wwise` | 消息发送到 Wwise Event |
| `ExternalDevice` | 消息发送到外部 MIDI 输出设备 |
| `None` | 输出已关闭 |

### `EIOType`

| 值 | 说明 |
| --- | --- |
| `IO_Input` | 输入端口 |
| `IO_Output` | 输出端口 |
| `IO_Both` | 输入和输出端口 |

### `EAkMessageType`

| 值 | MIDI 状态高位 | 说明 |
| --- | ---: | --- |
| `AMT_Note_None` | `0x0` | 无效/未指定消息 |
| `AMT_Note_Off` | `0x8` | Note Off |
| `AMT_Note_On` | `0x9` | Note On；力度 `0` 也表示 Note Off |
| `AMT_AfterTouch` | `0xA` | 单音符触后 |
| `AMT_CC` | `0xB` | Control Change |
| `AMT_Program_Change` | `0xC` | Program Change |
| `AMT_Channel_AfterTouch` | `0xD` | 通道触后 |
| `AMT_Pitch_Bend` | `0xE` | Pitch Bend |

### `EMessageParamType`

供 `ModifyAkMidiMessage` 选择要修改的字段：

- `MPT_NoteOffset`
- `MPT_Channel`
- `MPT_Data01`
- `MPT_Data02`

## Device 参数

### 设备枚举结果

`GetMidiDevice` 会清空传入的两个数组，然后分别加入一个虚拟端点和操作系统枚举到的物理设备：

```text
InputDevices:
  [0] Name="Unreal", Port=127
  [1...] 物理 MIDI 输入设备

OutputDevices:
  [0] Name="Wwise", Port=127
  [1...] 物理 MIDI 输出设备
```

虚拟端口 `127` 的含义取决于调用的接口：

| 调用 | Port | 结果 |
| --- | ---: | --- |
| `OpenMidiInputDevice` | `127` | 输入源设为 `Unreal` |
| `OpenMidiInputDevice` | 物理端口 | 输入源设为 `ExternalDevice` 并打开该端口 |
| `OpenMidiOutputDevice` | `127` | 输出目标设为 `Wwise` |
| `OpenMidiOutputDevice` | 物理端口 | 输出目标设为 `ExternalDevice` 并打开该端口 |

### 正确选择 Port

物理设备通常从端口 `0` 开始，但数组第 `0` 项已被虚拟端点占用。例如：

```text
InputDevices[0] = Unreal,     Port 127
InputDevices[1] = MIDI Keys, Port 0
InputDevices[2] = Pad,       Port 1
```

选择 `MIDI Keys` 时应传 `InputDevices[1].Port`，即 `0`，而不是数组下标 `1`。

### Device 调用规则

- 任何涉及物理设备的流程都必须先调用 `GetMidiDevice`。该接口不仅枚举设备，也会创建 RtMidi 对象并绑定输入回调。
- 端口号必须来自最新一次枚举结果。设备插拔后应重新枚举，不要缓存旧数组下标。
- 输入与输出分别编号；同名设备的输入端口和输出端口不保证相同。
- `127` 是 AkMIDI 保留的虚拟端口，不代表第 128 个物理设备。
- 使用完成后调用 `CloseMidiDevice`。关闭后不要继续发送，重新使用前应重新选择输入和输出。
- 底层 Wwise 音频回调为单播绑定。外部输入场景建议只使用一个活动的 `UAkMidiComponent`；后调用 `GetMidiDevice` 的组件会替换先前绑定。

## MIDI 参数

| 消息类型 | `Data01` | `Data02` |
| --- | --- | --- |
| Note On | 音高 `0-127` | 力度 `0-127` |
| Note Off | 音高 `0-127` | 释放力度 `0-127` |
| Note Aftertouch | 音高 `0-127` | 压力值 `0-127` |
| CC | 控制器编号 `0-127` | 控制器值 `0-127` |
| Program Change | Program 编号 `0-127` | 未使用，填 `0` |
| Channel Aftertouch | 压力值 `0-127` | 未使用，填 `0` |
| Pitch Bend | 低 7 位 | 高 7 位 |

Pitch Bend 的 14 位值为：

```text
Value = (Data02 << 7) | Data01
```

范围为 `0-16383`，中心值 `8192` 对应 `Data01=0`、`Data02=64`。

接口字段使用 `uint8`，但不会在所有路径中自动限制到 MIDI 的 7 位范围。调用方应保证 `Channel` 为 `0-15`，`Data01` 和 `Data02` 为 `0-127`。

## 使用流程

### 流程一：Unreal -> Wwise

该流程不访问物理 MIDI 设备，可以不调用 `GetMidiDevice`。

1. 在 Actor 上添加 `Ak MIDI Component`。
2. 为组件设置接收 MIDI 的 `AkAudioEvent`，或准备在发送时传入 Event。
3. 使用 `CreateAkMidiMessage` 创建 Note On：

   ```text
   NoteType   = AMT_Note_On
   Channel    = 0
   NoteOffset = 0
   Data01     = 60
   Data02     = 100
   ```

4. 把消息放入数组并调用 `PostMidiEvent`。
5. 音符结束时发送相同 Channel、相同 Data01 的 Note Off。
6. 需要停止该 Event 的全部 MIDI 播放时调用 `StopMidiEvent`。

不要只发送 Note On；没有对应的 Note Off 可能产生持续音。

### 流程二：外部设备 -> Wwise

1. 在 Actor 上添加 `Ak MIDI Component`，设置接收 MIDI 的 Wwise Event。
2. 调用 `GetMidiDevice`。
3. 在 `InputDevices` 中选择物理设备并读取其 `Port`。
4. 调用 `OpenMidiInputDevice(PhysicalInput.Port)`。
5. 调用 `OpenMidiOutputDevice(127)`，将输出目标设为 Wwise。
6. 可选：绑定 `OnMessageReceived`，用于 UI、记录或附加游戏逻辑。
7. 结束时调用 `CloseMidiDevice(IO_Input)` 或 `CloseMidiDevice(IO_Both)`。

`OnMessageReceived` 的消息对象来自组件内部对象池，后续可能被复用。需要跨帧保存时应立即复制消息字段，不要长期持有回调参数对象。当前 `Wwise2025.1.9` 中回调的 `DeltaTime` 可能为 `0`，不要依赖它进行精确节拍同步。

### 流程三：Unreal -> 外部设备

1. 调用 `GetMidiDevice`。
2. 在 `OutputDevices` 中选择物理设备并读取其 `Port`。
3. 调用 `OpenMidiInputDevice(127)`，将输入源设为 Unreal。
4. 调用 `OpenMidiOutputDevice(PhysicalOutput.Port)`。
5. 创建 MIDI 消息并调用 `PostMidiEvent`；此时 Event 可以为空。
6. 为每个 Note On 发送对应 Note Off。
7. 结束时调用 `CloseMidiDevice(IO_Output)` 或 `CloseMidiDevice(IO_Both)`。

### 流程四：使用 MIDI FX

1. 创建 `Ak MIDI Component` 的蓝图子类。
2. 重写 `InsertMidiFx`。
3. 在事件中修改并返回传入的 `UAkMidiMessage`。
4. 调用 `MidiFxBypass(false)` 启用 FX。
5. 不需要处理时调用 `MidiFxBypass(true)` 旁路 FX。

使用移调时，建议自行编写同时覆盖 Note On 和 Note Off 的处理，并把最终音高限制到 `0-127`。

## C++ 最小示例

```cpp
#include "AkMidiComponent.h"
#include "AkMidiFunctionLibrary.h"

bool SendMiddleC(UAkMidiComponent* MidiComponent, UAkAudioEvent* Event)
{
    if (!MidiComponent || !Event)
    {
        return false;
    }

    UAkMidiMessage* NoteOn = UAkMidiFunctionLibrary::CreateAkMidiMessage(
        EAkMessageType::AMT_Note_On,
        0,   // MIDI channel 1
        0,   // sample offset
        60,  // middle C
        100  // velocity
    );

    TArray<UAkMidiMessage*> Messages;
    Messages.Add(NoteOn);
    return MidiComponent->PostMidiEvent(Messages, Event);
}
```

该示例只发送 Note On。实际逻辑必须在合适的时机再发送相同通道和音高的 Note Off。

## 返回值与排查

`PostMidiEvent` 返回 `false` 时，检查以下条件：

- 组件是否有效。
- 消息数组是否非空。
- Unreal 主动发送时，输入源是否为 `Unreal`。
- 输出到 Wwise 时，Event 是否有效、SoundBank 是否已加载。
- Wwise SoundEngine 是否已经初始化。
- 输出到外部设备时，是否已执行 `GetMidiDevice` 并成功打开输出端口。

外部输入没有响应时，检查以下条件：

- 是否先调用 `GetMidiDevice` 再打开输入端口。
- 是否传入 `FMidiDevice.Port` 而非数组下标。
- 输出目标是否为 Wwise。
- 设备是否被其他程序独占，操作系统 MIDI 权限是否可用。
- 是否存在另一个组件在之后调用了 `GetMidiDevice` 并覆盖回调绑定。

## 当前限制

- 不处理 SysEx、MIDI Clock 和其他 System/Realtime 消息。
- 外部输入到外部输出直通在 `Wwise2025.1.9` 中不可靠。
- `OnMessageReceived.DeltaTime` 在 `Wwise2025.1.9` 中可能始终为 `0`。
- 不会统一自动校验 MIDI 通道、数据字节和移调后的音高范围。
- 多个组件同时处理外部输入时，共享的单播 Wwise 回调会由最后绑定的组件占用。
